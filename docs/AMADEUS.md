# ربط Amadeus

## 1) إنشاء مفاتيح API
1. أنشئ حساباً في [Amadeus for Developers](https://developers.amadeus.com/).
2. أنشئ تطبيقاً واحتفظ بـ API Key و API Secret.
3. ابدأ ببيئة الاختبار (Test). لا تستخدم الإنتاج قبل تفعيل صلاحيات الإنتاج من Amadeus.

## 2) إعداد المفاتيح محلياً
انسخ `.env.example` إلى `.env` ثم املأ:
```dotenv
AMADEUS_ENVIRONMENT=test
AMADEUS_CLIENT_ID=ضع_api_key_هنا
AMADEUS_CLIENT_SECRET=ضع_api_secret_هنا
APP_CURRENCY=EGP
```
لا ترفع `.env` إلى GitHub ولا ترسل المفاتيح في المحادثات.

## 3) تشغيل التطبيق
```powershell
pip install -r requirements.txt
streamlit run app.py
```
نفّذ بحثاً بتاريخ مستقبلي ومسار تدعمه بيئة الاختبار. بيانات Test ليست تغطية كاملة للسوق ولا تمثل ضماناً لتوفر كل رحلة مصرية.

## ما الذي ينفذه التكامل؟
- OAuth 2.0 Client Credentials للحصول على رمز وصول.
- Flight Offers Search عبر `/v2/shopping/flight-offers`.
- إرسال المسار والتاريخ والمسافرين ودرجة السفر والعملة.
- توحيد السعر والناقل ووقت الرحلة والتوقفات والمدة والأمتعة المتاحة.
- تجاهل العرض الفردي المشوه بدلاً من إسقاط نتائج البحث كلها.

## حدود مهمة
- الأسعار والتوافر قابلان للتغيير، ويجب إعادة التحقق من العرض قبل الحجز.
- Flight Offers Search لا يقدم بالضرورة رابط حجز مباشر للمستخدم؛ لذلك لا يخترع التطبيق رابطاً. نعرض مصدر العرض ونوضح غياب رابط الحجز، ويمكن إضافة مسار إعادة التسعير/التحقق ثم تكامل حجز مناسب لاحقاً.
- بيئة الاختبار قد تعيد نتائج محدودة أو لا تعيد نتائج لبعض المسارات والتواريخ.
- لا يتم تحويل العملات تلقائياً؛ العملة المطلوبة ترسل إلى المزود ويعرض التطبيق العملة التي أعادها.
